# Uncompose Project v0.1.0

First release. `uncompose-project` turns a directory into a project with a single
portable manifest, `uncompose.project.json`, recording each asset's identity
(sha256 + size) the moment it's registered and letting you verify, at any time,
that the files on disk still match.

## What it does

- `init`, `add`, `show`, `verify`, and `import`, standalone as `uncompose-project`
  and through root dispatch as `uncompose project`.
- `add` registers a file as an asset by hashing it; `verify` re-checks every
  registered asset against disk and reports `verified`, `modified`, or `missing`.
- `import` reads an evidence file and, by its `schema` URL, lands either a
  completed `uncompose` job (source asset, output stems, and the derivation
  linking them) or a `uncompose-compare` comparison record (an evaluation over
  assets the project already tracks) — idempotent by the evidence file's hash,
  so re-import is a no-op. See [`docs/import.md`](../import.md).
- Every write serializes behind an advisory lock (`<root>/.uncompose.project.lock`)
  with a blocking wait, so concurrent writers wait rather than corrupt or lose
  a write.
- Ships as a Linux `maturin` wheel: `pip install uncompose-project`.

## Schema policy

The manifest's `schema` field carries a major-only identifier URL,
`https://uncompose.org/schemas/project/v0/uncompose.project.schema.json`, compared
by exact string match. `v0` covers this entire pre-1.0 period: purely additive
optional fields never move the URL, but a breaking change (a field removed,
renamed, retyped, or repurposed) can ship between releases without one either —
that's what `v0` signals. There is no migration machinery in v0.1: if a manifest
written by an older v0.1.x release stops validating against a newer one, the
remedy is to regenerate it or hand-edit it to match. See
[uncompose#64](https://github.com/thedahm/uncompose/issues/64) for the full
policy and [ADR-0001](../adr/0001-adopt-manifest-schema-v0.md) for how this repo
adopted it.

## Known limitations

See [known limitations](../known-limitations.md) for the full list, including
Linux-only support and passive (not active) moved-path survival — there's no
`move` or `repair` command in v0.1.

## Try it

The [M5 demonstration project](https://github.com/thedahm/uncompose/tree/main/demo)
builds a populated manifest — one source asset, two derivations, an evaluation —
from synthetic fixtures in seconds, no GPU or model download required.
